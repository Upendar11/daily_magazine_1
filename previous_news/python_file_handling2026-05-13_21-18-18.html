§ 0 — Mental Model

A File Is a Pipe, Not a Room

Most beginners picture a file as a room — you walk in, grab what you want, walk out. The accurate picture is a pipe connected to a descriptor: the operating system hands you a numbered slot (a file descriptor) and routes everything through it.

Python wraps that descriptor in a file object and gives you methods. But the OS has a hard limit — roughly 1,024 open descriptors per process. Leave files open and you hit OSError: Too many open files.

There's a second danger: writes don't go straight to disk. They sit in a buffer — like cash on your desk instead of in the bank. Until close() is called, that buffer may never be flushed. The file on disk is incomplete, as if a transaction was never committed.

"A file is a sequence of bytes accessed through a file descriptor. You MUST close it — or the OS runs out of pipes and your data stays in limbo."

§ 0 — Mental Model

Danger 1 — Descriptor Leak

  • OS limit: ~1,024 open files
  • Symptom: OSError: Too many open files
  • Fix: Always close()

Danger 2 — Unflushed Buffer

  • Writes go to buffer first
  • Disk only updated on close() / flush()
  • Unflushed = data is lost on crash

§ 1 & 2 — open() and File Modes

Every Mode Is a Contract

When you call open(), you make a contract with the OS. The mode argument tells it what you intend to do — and the OS enforces it. Get the mode wrong and you silently erase data or corrupt a binary file.

'r'
Read Only
Opens an existing file for reading. Raises FileNotFoundError if the file doesn't exist. Nothing is created or changed.
'w'
Write (Overwrite)
Creates the file if needed, erases all existing content silently if it does exist. Use with caution.
⚠ Erases existing content
'a'
Append
Opens for writing, but preserves existing content and adds new data at the end. Safe for logs and growing files.
'x'
Exclusive Create
Creates a new file. Raises FileExistsError if the file already exists. The safest way to avoid accidental overwrites.
🛡 Fails safely if file exists
'b'
Binary Suffix
Append to any mode: 'rb', 'wb'. Returns bytes instead of str. Required for images, PDFs, ZIPs — anything that isn't plain text.
🖼 Images need 'b'
't'
Text Suffix (Default)
The default mode. Returns str, translates line endings. Omitting it is the same as writing 'rt' or 'wt'.

The 'x' pattern with error handling is your guard against overwriting outputs you don't want to lose:

safe_create.py 
# Safe create — never overwrite
try:
    with open("report.txt", "x") as f:
        f.write("Analysis complete\n")
except FileExistsError:
    print("File already exists — skipping")

# Other key examples
open("log.txt",    "a")   # append without overwriting
open("image.png",  "rb")  # binary read (images need 'b')
open("output.txt", "w",  encoding="utf-8")  # write with encoding
⚠️
The 'w' Trap

'w' mode erases the file the instant you open it — before you write a single byte. There is no undo. If you meant to append, use 'a'. If you want to fail safely rather than overwrite, use 'x'.

Chapter II — The Patterns

Context Manager, Reading & Writing

The with statement is the single most important pattern in file handling. Layer on top of it the five reading strategies and the three writing methods, and you can handle almost any file task correctly.

Covers § 3 · § 4 · § 5

§ 3 — Context Manager

The with Statement: Your Safety Net

The context manager is Python's answer to "what if an error happens before I call close()?" It guarantees the file is closed regardless — success or exception. Think of it as a try/finally block that Python writes for you, invisibly.

"with open(…) is not a style choice. It is the correct way to open files. Every other way is a bug waiting for bad luck."

§ 3 — Context Manager

❌ Wrong Way

f = open("file.txt")
data = f.read()
# If read() crashes,
# close() is never called
f.close()

✅ Right Way

with open("file.txt") as f:
    data = f.read()
# Closed automatically here,
# even if read() raised

You can open multiple files in one with statement — useful for copy operations:

multi_file.py 
# Both files closed automatically, even on error
with open("in.txt") as src, open("out.txt", "w") as dst:
    dst.write(src.read())

§ 4 — Reading Text

Five Ways to Read — One Winner

Python gives you five reading patterns. For most real-world work — especially large files — only one is appropriate. Knowing which to pick prevents memory exhaustion and hard-to-debug bugs.

  • f.read() Entire file as one big string. Loads everything into memory. Fine for small files, dangerous for large ones.
  • f.readline() One line per call. You control iteration manually. Rarely needed — the for loop is cleaner.
  • f.readlines() Returns a list of all lines. Loads everything into memory. Same caveat as .read() — avoid on large files.
  • for line in f ★ BEST for large files. Python streams one line at a time — constant memory, no matter how big the file.
  • f.read(n) Read exactly n characters. Used for binary chunking or fixed-width parsing.
filter_names.py 
# Filter names containing 'a' — streaming, memory-safe
with open("names.txt", encoding="utf-8") as f:
    for line in f:
        if 'a' in line:
            print(line.strip())  # strip() removes trailing \n

# Output: alice, carol, dave  (bob skipped)
# Note: every line from a file includes \n — always .strip()
💡
Strip Your Lines

Every line read from a text file includes a trailing \n character. Call line.strip() to remove leading and trailing whitespace, or line.rstrip('\n') to remove only the newline.

§ 5 — Writing Text

Three Writing Methods: Know Your Newlines

The main source of bugs when writing files is newline handling. Each method treats newlines differently — pick the wrong one and you either miss line breaks or double them.

  • f.write(s) Writes the string exactly as given. You must supply the newline — Python won't add one. Write f.write("hello\n") not f.write("hello").
  • f.writelines(lst) Writes each item from the list. Does NOT add newlines between items. Each string in the list must already contain \n.
  • print(…, file=f) Adds a newline automatically. Cleanest for human-readable line-by-line output. Familiar syntax, no newline management needed.
write_cities.py 
# Using print(file=f) — automatic newlines, cleanest syntax
with open("cities.txt", "w", encoding="utf-8") as f:
    print("london", file=f)
    print("paris",  file=f)
    print("tokyo",  file=f)

# Using f.write() — you supply the \n
with open("cities.txt", "w", encoding="utf-8") as f:
    f.write("london\n")   # \n required
    f.write("paris\n")
    f.write("tokyo\n")

# Using f.writelines() — items must contain \n already
cities = ["london\n", "paris\n", "tokyo\n"]
with open("cities.txt", "w", encoding="utf-8") as f:
    f.writelines(cities)

§ 6 — Text vs Binary Mode

Two Worlds, One Wrong Choice

Python's file system operates in two fundamentally different modes. Picking the wrong one for your content type doesn't raise an error — it silently corrupts your file.

Text Mode 't' (default)

  • Returns str
  • Translates \r\n → \n
  • Requires encoding
  • Use for .txt, .csv, .json, .py

Binary Mode 'b'

  • Returns bytes
  • No newline translation
  • No encoding arg
  • Use for .png, .pdf, .zip, .exe
💥
The Image Corruption Trap

Opening a .png or any binary file in text mode corrupts it. Python's text layer translates byte sequences that look like line endings — destroying the binary structure. Always use 'rb' / 'wb' for non-text files.

binary_copy.py 
# Safe binary copy — preserves every byte exactly
with open("image.png", "rb") as src:
    data = src.read()  # returns bytes, not str

with open("image_copy.png", "wb") as dst:
    dst.write(data)

# Or in one block:
with open("in.png", "rb") as s, open("out.png", "wb") as d:
    d.write(s.read())

§ 7 — Encoding

UTF-8 Is Not the Default (On Windows)

This is one of the most common portability bugs in Python. When you omit the encoding argument, Python uses the platform's locale default — cp1252 on many Windows systems, UTF-8 on Linux/Mac. Code that works on your machine silently breaks on a colleague's.

The rule is simple: always specify encoding='utf-8' explicitly. No exceptions for text files.

"encoding='utf-8' is not optional pedantry. It is the difference between code that works everywhere and code that breaks on deployment."

§ 7 — Encoding
encoding_examples.py 
# Always explicit — works the same on all platforms
with open("drinks.txt", "w", encoding="utf-8") as f:
    f.write("café au lait\n")   # é survives correctly

# Error handling options for bad bytes
with open("messy.txt", encoding="utf-8", errors="replace") as f:
    data = f.read()   # bad bytes → replacement char (safe)

with open("messy.txt", encoding="utf-8", errors="ignore") as f:
    data = f.read()   # bad bytes silently dropped

# Excel CSV trap — Excel writes a BOM marker at start
with open("export.csv", encoding="utf-8-sig") as f:
    data = f.read()   # utf-8-sig strips the BOM automatically
📊
Excel CSV Trap

CSVs exported from Excel often begin with a BOM (Byte Order Mark) character. Use encoding='utf-8-sig' instead of plain 'utf-8' to strip it automatically — otherwise you'll see a mysterious ï»¿ at the start of your first field.

The Golden Rules

Eight Rules That Prevent Every Common Bug

These eight rules were distilled from the session notes. Violate one and you'll almost certainly lose data, corrupt a file, or write non-portable code. Memorise them in order.

1
🔒
Always use with open()
The context manager guarantees the file is closed — even on exceptions. No exceptions to this rule.
2
🌐
Always specify encoding
Write encoding='utf-8' on every text file open. Platform defaults differ. UTF-8 is universal.
3
🖼
Use 'b' for non-text
Images, PDFs, ZIPs, executables — anything that isn't plain text requires binary mode to avoid corruption.
4
📋
newline='' with CSV
When using the csv module, open with newline='' to prevent double line-ending insertion.
5
🌊
Iterate large files
For large files, use for line in f. Never .read() or .readlines() on files that may not fit in memory.
6
⚛️
Atomic writes for critical output
Write to a temp file, fsync(), then rename(). A crash mid-write won't corrupt the real file.
7
🛡
Use 'x' to protect outputs
For outputs you must never overwrite, use 'x' mode. It raises FileExistsError rather than silently erasing data.
8
📊
utf-8-sig for Excel CSVs
Use encoding='utf-8-sig' when reading Excel-exported CSVs to automatically strip the BOM character.
